## Locked decisions

### Library

Use a narrow wrapper around `nostr-tools@2.24.1`. It supplies NIP-01 event construction, NIP-19 decoding, signing, verification, and filters while leaving Torana in control of NIP-42 sequencing, Buzz channel tags, replay cursors, and NIP-OA policy. Its license is compatible with Torana's MIT license. Its signing path uses the Noble curve/hash packages, whose projects publish audit information. The spike also verifies Buzz's exact NIP-OA golden vector, so Buzz-specific tag logic does not depend on a hand-rolled cryptographic primitive.

### Default subscriptions

Use distinct subscriptions instead of one broad wildcard:

| Purpose                    | Kinds enabled by default | Required tags                | Turn-producing?                 |
| -------------------------- | ------------------------ | ---------------------------- | ------------------------------- |
| Stream v1/v2 compatibility | `9`, `40002`             | `#h=<channel>`, `#p=<agent>` | yes, after author/mention gates |
| Message mutation state     | `40003`, `5`, `9005`     | `#h=<channel>`               | no                              |
| Membership lifecycle       | `44100`, `44101`         | global `#p=<agent>`          | no                              |

Reactions (`7`), forums (`45001`–`45003`), diffs (`40008`), presence (`20001`), typing (`20002`), canvas (`40100`), and workflow events (`46001`–`46031`) are known but remain feature-gated. Attachments are `imeta` tags on message events and Blossom objects; kind `1063` is not a second default message subscription. This minimal default preserves current message behavior and avoids silently creating turns for control or rich-surface events.

### Membership notification contract

The authoritative contract at the pinned commit is:

- add is relay-signed kind `44100`; remove is relay-signed kind `44101`;
- both are global events with `p=<affected pubkey>` and `h=<channel UUID>`;
- subscribe globally by the endpoint pubkey, not by channel;
- exact event-ID dedup handles reconnect overlap and same-second events;
- removal closes the channel subscription and prevents further cursor advancement for that channel; add subscribes from the notification timestamp with overlap.

## Local protocol evidence

The tracked spike at [`../spike/buzz-transport/`](../spike/buzz-transport/) passes these checks:

1. NIP-42 challenge response is signed and bound to the exact relay URL and challenge.
2. A closed fake relay rejects a key without a cryptographically valid NIP-OA tag and accepts the valid tag on both AUTH and published events.
3. The upstream `buzz-sdk` NIP-OA vector verifies byte-for-byte under the TypeScript wrapper.
4. Membership kind `39002` discovery yields a channel from its `d` tag.
5. Intake is scoped by `h` and `p`, and every inbound event ID/signature is verified locally.
6. Direct and nested replies use Buzz's NIP-10 tag shapes and are signed before publication.
7. Reconnect replays an overlap and exact event-ID dedup rejects the repeated mention.
8. Replaying the exact same signed outbound event receives a second successful `OK` with duplicate semantics from the fake relay.
9. The installed Rust `buzz` CLI produces a kind `9` stream event and NIP-98 request that the TypeScript wrapper verifies. Rebuilding the unsigned fields in TypeScript yields the identical event ID and pubkey.

## Capacity gate

The local idle-process measurements are tracked in [`../spike/buzz-transport/capacity-baseline.json`](../spike/buzz-transport/capacity-baseline.json). At the stable 1/2/8 points, Claude used approximately 357–372 MiB RSS and 30 FDs per resident invocation; Codex used approximately 46 MiB RSS and 38 FDs per concurrent invocation. The 32-Claude point spawned helper processes and is a total-load observation, not a clean per-session coefficient.

The authenticated provider-turn sweep is tracked in [`../spike/buzz-transport/capacity-authenticated.json`](../spike/buzz-transport/capacity-authenticated.json). All 86 minimal turns succeeded across 1/2/8/32-way runs for both Claude Code `2.1.220` and `codex-cli 0.146.0`. At 32-way concurrency, Claude peaked at 8.92 GiB RSS and 1,490 FDs; Codex peaked at 5.64 GiB RSS and 2,506 FDs. The single-turn Claude peak of 445.53 MiB is the conservative per-session coefficient because every higher-concurrency run used less RSS per invocation.

The authenticated Railway CLI reports the production `agent-team` service as one `us-west2` replica with an actual 32,768 MB memory ceiling. Its preceding 24-hour memory average was 417.20 MB and maximum was 808.52 MB. Capacity calculations use the larger 808.52 MB gateway baseline, the conservative 445.53 MiB Claude coefficient, and an additional 25% macOS-to-Linux/platform margin:

```text
32 sessions × 445.53 MiB × 1.25 + 808.52 MB = 18,629.77 MB
headroom = 43.1% of the measured 32,768 MB ceiling
```

The approved shipped defaults are therefore:

| Setting                                   | Approved value |
| ----------------------------------------- | -------------- |
| `sessions.max_per_agent`                  | `8`            |
| `sessions.max_global`                     | `32`           |
| `sessions.max_concurrent_turns_per_agent` | `2`            |
| `sessions.max_concurrent_turns_global`    | `12`           |

This exceeds the required 30% memory headroom by 13.1 percentage points. The 12-turn scheduler ceiling is independently conservative: applying the same coefficient and safety factor plus the gateway maximum projects about 7.49 GB, or 77.1% headroom. `max_global: 64` remains rejected. These values close the production capacity gate for the measured deployment; a material Railway plan/limit or runner-version change must rerun the probe.

## Phase 0 closeout

There are no remaining Phase 0 blockers. All gates in §11 of the implementation plan have reproducible evidence, and no additional internal design inconsistency is known. Phase 1 may start using the approved session defaults above.
